## 1. Executive Summary

This document defines the implementation plan for geocoding 945 DM (Daerah Mengundi) centroid coordinates using a **Google Maps Geocoding API (primary) → Nominatim (fallback) → D1 Cloudflare cache** architecture. The goal is to replace the current synthetic grid-based DM centroids with real geocoded coordinates derived from DM/locality name lookups, improving spatial accuracy for the bubble visualization layer and providing a foundation for Phase 5B (individual voter point mapping).

### Key Decisions

| Decision | Choice | Rationale |
|----------|--------|----------|
| Primary geocoder | Google Maps Geocoding API (DEV key) | Best accuracy for Malaysian addresses, component filtering (`country:MY`), 3,000 QPM capacity |
| Fallback geocoder | Nominatim (public instance) | Free, no API key needed, acceptable accuracy in urban Selangor |
| Cache storage | Cloudflare D1 (`geocode_cache` table) | Native integration with Workers, sub-10ms reads, free tier sufficient |
| Cache invalidation | Google: 30-day TTL, Nominatim: 90-day TTL | Per Google's caching policy; Nominatim data changes less frequently |
| Address format | `{dm_name}, {dun_name}, Selangor, Malaysia` | Hierarchical locality string maximizes match accuracy for both APIs |

### Scope

- **In scope**: Geocode all 945 DM names to latitude/longitude coordinates; store in D1; expose via API; update frontend to use geocoded centroids
- **Out of scope**: Individual voter address geocoding (Phase 5B); DM boundary polygon acquisition; PMTiles generation

## 2. Current State Analysis

### 2.1 What Exists Today

The current DM centroids are **synthetic grid points** generated by `scripts/generate_dm_centroids.py` using a Shapely grid-in-polygon strategy. For each DUN polygon, a regular grid of points at 0.004° spacing (~350m at 3°N) is created, and DMs are assigned to sequential grid points sorted by voter count (largest first).

**Current centroid quality:**

| Metric | Value |
|--------|-------|
| Total DM centroids | 945 (all populated) |
| Coordinate range (lng) | 100.812638 – 101.792097 |
| Coordinate range (lat) | 2.717220 – 3.815666 |
| Zero/NULL coordinates | 0 |
| Duplicate coordinates | 0 |
| **Real geocoded?** | **No — synthetic grid points inside DUN polygons** |

**Current data flow:**

```
scripts/generate_dm_centroids.py
  → dm_centroids.geojson (static, 849 KB, 34K lines)
  → merged into 0004_load_dms.sql by scripts/build_d1_load.py
  → dms.centroid_lng / dms.centroid_lat in D1
  → /api/dm?format=geojson (GeoJSON API)
  → MapDashboard.tsx (bubble layer at zoom 11+)
```

### 2.2 What Needs to Change

| Aspect | Current | Target |
|--------|---------|--------|
| Centroid source | Synthetic grid-in-polygon | Real geocoded coordinates |
| Accuracy | ~350m grid spacing, not tied to real locations | Address-level or locality-level accuracy |
| DMs within same DUN | Evenly distributed on grid | Clustered at real locality positions |
| Data freshness | Static, regenerated manually | Cache with TTL, refreshable via API |
| Fallback chain | None (static file only) | D1 cache → Google API → Nominatim → synthetic fallback |

### 2.3 Constraints

1. **DM names are electoral divisions, not postal addresses.** Google and Nominatim won't resolve "DM: 01.BANDAR COUNTRY HOME 1" directly. The geocoding query must be constructed from the DM name + DUN name + state context.
2. **Source data has 0% GPS availability** (per `ANALYSIS.md`). No coordinates exist in the raw voter xlsx files.
3. **OSM coverage in Malaysia is patchy.** Urban areas (Petaling Jaya, Subang Jaya, Shah Alam) have good coverage. Rural DMs (Sabak Bernam, Kuala Selangor) may only get locality/postcode-level precision.
4. **Google's caching policy allows 30-day storage.** Cached results must be refreshed periodically.
5. **D1 free tier: 5M reads/day, 100K writes/day, 5GB storage.** More than sufficient for 945 DM records with cache metadata.

## 4. Google Maps Geocoding API (Primary)

### 4.1 API Details

| Property | Value |
|----------|-------|
| Endpoint | `https://maps.googleapis.com/maps/api/geocode/json` |
| Method | GET |
| Auth | `key` query parameter (API key provided at implementation time) |
| Rate limit | 3,000 QPM (~50 QPS) combined client+server |
| Pricing (post-March 2025) | $5.00/1K requests (0–100K tier), 10K free/month |
| Caching policy | Results cacheable for **30 days** |
| Component filtering | `components=country:MY&administrative_area=Selangor` |

### 4.2 Request Construction

For each DM, construct the geocoding query as follows:

```
Base query:  "{dm_clean_name}, {dun_name}, Selangor, Malaysia"

Example:
  DM code:  "01.BANDAR COUNTRY HOME 1"
  DUN name: "SUNGAI AIR TAWAR"
  → Query: "Bandar Country Home 1, Sungai Air Tawar, Selangor, Malaysia"

  DM code:  "05.SEXSIEN 7"
  DUN name: "SHAH ALAM"
  → Query: "Seksyen 7, Shah Alam, Selangor, Malaysia"
```

**Query normalization rules:**
1. Strip DM numeric prefix (everything before and including the first `.`)
2. Apply common Malay transliteration fixes: `SEKSIEN` → `Seksyen`, `SEXSIEN` → `Seksyen`, `KAMPUNG` → `Kampung`, `TAMAN` → `Taman`, `BANDAR` → `Bandar`, `JALAN` → `Jalan`
3. Always append DUN name, "Selangor", and "Malaysia" for context
4. Use `components=country:MY` to constrain results to Malaysia
5. Set `region=my` for bias toward Malaysian results

### 4.3 Response Parsing

```typescript
interface GeocodeResult {
  lat: number;
  lng: number;
  accuracy: 'rooftop' | 'range_interpolated' | 'geometric_center' | 'approximate';
  location_type: string;
  formatted_address: string;
  place_id: string;
}
```

Parse logic:
1. Check `status === 'OK'`
2. Take `results[0]` (highest confidence)
3. Extract `geometry.location.lat`, `geometry.location.lng`
4. Map `geometry.location_type` to accuracy level
5. Validate coordinates fall within Selangor bounds (lng: 100.5–102.0, lat: 2.5–4.0)
6. If outside bounds, try `results[1]` if available, else mark as unresolved

### 4.4 Error Handling

| Google Response | Action |
|-----------------|--------|
| `OK` | Parse result, cache with 30-day TTL |
| `ZERO_RESULTS` | Cache as "unresolved" with 7-day TTL (avoid re-querying) |
| `OVER_QUERY_LIMIT` | Immediately fall through to Nominatim |
| `REQUEST_DENIED` | Log error, fall through to Nominatim |
| `INVALID_REQUEST` | Log malformed query, skip this DM |
| Network error / timeout | Retry once after 1s, then fall through to Nominatim |

## 5. Nominatim (Fallback)

### 5.1 API Details

| Property | Value |
|----------|-------|
| Endpoint | `https://nominatim.openstreetmap.org/search` |
| Method | GET |
| Auth | None (mandatory `User-Agent` or `Referer` header) |
| Rate limit | **1 req/sec** (interactive), **4 QPM** (bulk scripts) |
| Caching policy | Results **must** be cached on your side |
| Country filter | `countrycodes=my` |
| Format | `format=jsonv2` (preferred, includes extra fields) |

### 5.2 Request Construction

Same query string as Google (hierarchical locality). Additional Nominatim-specific parameters:

```
https://nominatim.openstreetmap.org/search?
  q={encoded_query}&
  countrycodes=my&
  format=jsonv2&
  limit=1&
  addressdetails=1&
  extratags=1

Headers:
  User-Agent: SLGRVTRS-Dashboard/1.0 (research@ritz-analytics.workers.dev)
```

### 5.3 Response Parsing

```typescript
interface NominatimResult {
  lat: string;   // Note: Nominatim returns strings, not numbers
  lon: string;
  display_name: string;
  type: string;         // e.g., 'suburb', 'village', 'residential', 'city'
  importance: number;   // 0.0–1.0 ranking
  address: {
    suburb?: string;
    village?: string;
    city_district?: string;
    city?: string;
    state?: string;
    country?: string;
  };
}
```

Parse logic:
1. Check non-empty array response
2. Take first result (highest importance)
3. Parse `lat`/`lon` as floats
4. Validate coordinates within Selangor bounds
5. Map `type` to accuracy level: `residential`/`suburb` → `exact`, `village`/`town` → `locality`, `city`/`county` → `district`

### 5.4 Rate Limiting Strategy

Since Nominatim's public instance enforces **1 request/second** for interactive use and **4 requests/minute** for bulk scripts, the implementation MUST enforce:

```typescript
const NOMINATIM_MIN_INTERVAL_MS = 1100; // 1.1s between requests (safety margin)
// For bulk mode:
const NOMINATIM_BULK_INTERVAL_MS = 16000; // 16s between requests (4 QPM with margin)
```

**Important**: If processing more than ~100 DMs via Nominatim, consider self-hosting. A Malaysia-only Nominatim instance on a $10–20/mo VPS (2–4GB RAM, Docker) eliminates all rate limits and processes all 945 DMs in ~5–10 minutes.

### 5.5 Error Handling

| Scenario | Action |
|----------|--------|
| Empty results `[]` | Cache as "unresolved" with 7-day TTL |
| HTTP 429 (rate limited) | Wait 60s, retry once, then return 408 to caller |
| HTTP 5xx / timeout | Retry once after 2s, then fall through to unresolved |
| Network error | Return error, allow caller to retry later |

## 6. D1 Cache Layer

### 6.1 Schema Design

```sql
-- Migration: 0005_geocode_cache.sql

CREATE TABLE IF NOT EXISTS geocode_cache (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    query_hash      TEXT    NOT NULL,  -- SHA-256 of normalized query string
    raw_query       TEXT    NOT NULL,  -- Original address query sent to API
    dm_code         TEXT,              -- Associated DM code (nullable for ad-hoc queries)
    latitude        REAL,              -- NULL if unresolved
    longitude       REAL,              -- NULL if unresolved
    accuracy_level  TEXT,              -- 'exact' | 'locality' | 'district' | 'state' | 'unresolved'
    source          TEXT    NOT NULL,  -- 'google' | 'nominatim' | 'synthetic' | 'manual'
    formatted_address TEXT,            -- Full address from geocoder response
    place_id        TEXT,              -- Google place_id or Nominatim osm_id
    response_json   TEXT,              -- Truncated API response for debugging (max 2KB)
    country_code    TEXT    DEFAULT 'MY',
    state           TEXT    DEFAULT 'Selangor',
    hit_count       INTEGER NOT NULL DEFAULT 0,
    created_at      TEXT    NOT NULL DEFAULT (datetime('now')),
    expires_at      TEXT    NOT NULL,  -- TTL-based expiry
    updated_at      TEXT    NOT NULL DEFAULT (datetime('now'))
);

-- Core lookup index (most queries use this)
CREATE UNIQUE INDEX IF NOT EXISTS idx_geocode_query_hash
    ON geocode_cache(query_hash);

-- DM code lookup (for batch updates to dms table)
CREATE INDEX IF NOT EXISTS idx_geocode_dm_code
    ON geocode_cache(dm_code);

-- Expiry cleanup (for scheduled cache invalidation)
CREATE INDEX IF NOT EXISTS idx_geocode_expires
    ON geocode_cache(expires_at);

-- Source filtering (analytics/debugging)
CREATE INDEX IF NOT EXISTS idx_geocode_source
    ON geocode_cache(source);
```

### 6.2 Query Hash Generation

```typescript
import { createHash } from 'crypto';  // Node.js crypto (available in Workers)

function normalizeQuery(query: string): string {
  return query
    .toLowerCase()
    .replace(/\s+/g, ' ')
    .replace(/,\s*/g, ', ')
    .trim();
}

function hashQuery(query: string): string {
  return createHash('sha256').update(normalizeQuery(query)).digest('hex');
}
```

### 6.3 TTL Strategy

| Source | TTL | Rationale |
|--------|-----|----------|
| Google Maps | 30 days | Google's caching policy maximum |
| Nominatim | 90 days | OSM data changes infrequently; Nominatim has no explicit limit |
| Unresolved | 7 days | Re-attempt after a week (data may have been updated) |
| Synthetic fallback | Never expires | Our generated centroids don't change unless DUN boundaries change |
| Manual override | Never expires | Explicitly set by admin |

### 6.4 Cache Operations

```typescript
// Lookup
const hash = hashQuery(query);
const cached = await env.DB.prepare(
  `SELECT * FROM geocode_cache
   WHERE query_hash = ? AND expires_at > datetime('now')`
).bind(hash).first();

// Insert (after successful geocode)
await env.DB.prepare(
  `INSERT INTO geocode_cache
   (query_hash, raw_query, dm_code, latitude, longitude,
    accuracy_level, source, formatted_address, place_id,
    response_json, expires_at)
   VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?, datetime('now', '+30 days'))`
).bind(hash, rawQuery, dmCode, lat, lng, accuracy, source,
       formattedAddress, placeId, responseJson).run();

// Increment hit_count on cache hit
await env.DB.prepare(
  `UPDATE geocode_cache SET hit_count = hit_count + 1 WHERE query_hash = ?`
).bind(hash).run();

// Batch insert (for pipeline)
const stmts = results.map(r =>
  env.DB.prepare(`INSERT OR REPLACE INTO geocode_cache ...`).bind(...)
);
await env.DB.batch(stmts);

// Expired entry cleanup (run periodically)
await env.DB.prepare(
  `DELETE FROM geocode_cache WHERE expires_at < datetime('now')`
).run();
```

### 6.5 D1 Performance Considerations

- **D1 free tier**: 5M reads/day, 100K writes/day, 5GB storage — all sufficient for 945 cache entries with metadata
- **Read latency**: ~8ms P99 (local replica) for indexed lookups
- **Write latency**: ~200–300ms (primary node) — acceptable for batch pipeline
- **`db.batch()`**: Use for bulk inserts (up to 100 statements per batch in D1)
- **Row width**: Keep `response_json` truncated to 2KB max — D1 replicates rows globally, large blobs increase read costs
- **Indexes**: All 4 indexes fit easily within D1's storage and query planner capabilities

## 8. Batch Geocoding Pipeline

### 8.1 Recommended Approach: Local Python Script + D1 HTTP API

Due to Cloudflare Workers' execution time constraints, the recommended approach for the initial batch geocoding of all 945 DMs is a **local Python script** that:

1. Reads DM data from D1 via the HTTP API (or from local `dm.json` + `dm_centroids.geojson`)
2. Calls Google Maps Geocoding API directly (with the user-provided DEV key)
3. Falls back to Nominatim for any failures
4. Writes results to D1 via the HTTP API (batch INSERT, 50 per request)
5. Updates `dms.centroid_lng/centroid_lat` with improved coordinates
6. Regenerates the static `dm_centroids.geojson` fallback file

**Why not a Worker-based batch?**
- Workers free tier: 10ms CPU, 30s wall clock — far too short for 945 API calls
- Workers paid tier: 15 min CPU — technically possible but wasteful for a one-time operation
- Local script has no timeout, full Python ecosystem, easier debugging
- The API routes (`/api/geocode`) are designed for **ongoing** single-query lookups, not bulk processing

### 8.2 Script: `scripts/geocode_dm_batch.py`

```
Usage:
  python scripts/geocode_dm_batch.py \
    --google-key YOUR_API_KEY \
    --d1-account-id 20b9d9b232ee8f29aa3e626530f0da09 \
    --d1-database-id 59afb76e-a3a2-4e2a-b18d-857f9f5704fb \
    --d1-token CF_API_TOKEN \
    --source auto \
    --google-qps 45 \
    --nominatim-qps 1 \
    --dry-run   # preview what would be geocoded without making API calls
```

**Script flow:**

1. **Load DM list** from D1 or local files
2. **Check existing cache** in D1 `geocode_cache` table — skip already-geocoded DMs (unless `--force`)
3. **Construct queries** using normalization rules (Section 4.2)
4. **Geocode in sequence** with rate limiting:
   - Google Maps: 45 QPS (configurable, stays under 50 QPS limit)
   - Nominatim fallback: 1 QPS (respects public policy)
5. **Validate coordinates** within Selangor bounds (lng: 100.5–102.0, lat: 2.5–4.0)
6. **Write to D1** via HTTP API batch endpoint (50 INSERTs per request)
7. **Update `dms` table** with new centroid coordinates (only if geocoded coords differ from existing)
8. **Generate report**: total geocoded, by source, by accuracy, unresolved list
9. **Regenerate `dm_centroids.geojson`** static fallback file

### 8.3 Query Construction Logic

```python
# Pseudocode for query normalization
MALAY_FIXES = {
    'SEKSIEN': 'Seksyen', 'SEXSIEN': 'Seksyen', 'SEKSYEN': 'Seksyen',
    'KAMPUNG': 'Kampung', 'KG ': 'Kampung ',
    'TAMAN': 'Taman', 'TMN ': 'Taman ',

    'JALAN': 'Jalan', 'JLN ': 'Jalan ',
    'PERSIARAN': 'Persiaran', 'PSR ': 'Persiaran ',
    'LEBUH': 'Lebuh', 'LBH ': 'Lebuh ',
    'LOJONG': 'Lojong',
    'MUKIM': 'Mukim',
}

def build_geocode_query(dm_code: str, dun_name: str) -> str:
    # Strip numeric prefix: "01.BANDAR COUNTRY HOME 1" → "BANDAR COUNTRY HOME 1"
    name = dm_code.split('.', 1)[1] if '.' in dm_code else dm_code

    # Apply Malay transliteration fixes
    for old, new in MALAY_FIXES.items():
        name = name.replace(old, new)

    # Build hierarchical query
    return f"{name}, {dun_name}, Selangor, Malaysia"
```

## 9. Malaysian Address Geocoding Challenges

### 9.1 Core Problem

DM (Daerah Mengundi) names are **electoral administrative divisions**, not standard postal addresses. Geocoding APIs are designed to resolve postal addresses, street addresses, and named places — not electoral district codes. This creates a fundamental mismatch that must be addressed through query construction strategy.

### 9.2 Challenge Matrix

| Challenge | Impact | Mitigation |
|-----------|--------|------------|
| **DM names not recognized as addresses** | Google/Nominatim may return ZERO_RESULTS | Append DUN name + state + country for hierarchical context |
| **Malay-language locality names** | Transliterations may not match English labels in geocoder databases | Apply normalization fixes (SEKSIEN→Seksyen, KG→Kampung, etc.) |
| **OSM coverage gaps in rural Selangor** | Nominatim may only return district-level precision for rural DMs | Accept lower accuracy; use Google as primary for better rural coverage |
| **DMs spanning multiple localities** | A single DM name may not map to a single point | Use the most populated locality within the DM; note multi-locality DMs for manual review |
| **Duplicate/similar DM names across DUNs** | "Seksyen 7" exists in multiple DUNs | Always include DUN name in query to disambiguate |
| **Boundary changes between elections** | DM boundaries shift after each delimitation exercise | Cache with TTL; manual review after boundary changes |
| **Non-standard abbreviations** | "BJ", "PJ", "KJ" in DM names | Maintain abbreviation expansion table in the script |

### 9.3 Expected Accuracy Distribution

Based on OSM coverage analysis and Google's Malaysian data quality:

| Area Type | Estimated DMs | Expected Accuracy |
|-----------|---------------|-------------------|
| Urban (PJ, Subang, Shah Alam, Ampang) | ~400 | `exact` (address-level) — 80%+ match rate |
| Suburban (Kajang, Bangi, Rawang, Sepang) | ~350 | `locality` (neighbourhood-level) — 70%+ match rate |
| Rural (Sabak Bernam, Kuala Selangor, Hulu Selangor) | ~195 | `district` (town-level) — 50%+ match rate |

**Overall expected resolution rate: 85–90%** of 945 DMs should get usable coordinates. The remaining 10–15% (primarily rural) may require manual placement or acceptance of district-level precision.

**Rate limiter implementation (token bucket):**

```python
import time

class RateLimiter:
    def __init__(self, qps: float):
        self.min_interval = 1.0 / qps
        self.last_request = 0.0

    def wait(self):
        now = time.monotonic()
        elapsed = now - self.last_request
        if elapsed < self.min_interval:
            time.sleep(self.min_interval - elapsed)
        self.last_request = time.monotonic()

# Usage
google_limiter = RateLimiter(qps=45)
nominatim_limiter = RateLimiter(qps=1)  # Respect 1 req/sec policy
```

## Appendix C: API Route Skeleton Code

### `POST /api/geocode`

```typescript
// dashboard/src/app/api/geocode/route.ts
import { getCloudflareContext } from '@opennextjs/cloudflare';
import { NextResponse } from 'next/server';
import { createHash } from 'crypto';

interface GeocodeRequest {
  query: string;
  dm_code?: string;
  dun_code?: string;
}

interface GeocodeResponse {
  dm_code: string | null;
  query: string;
  latitude: number | null;
  longitude: number | null;
  accuracy: string;
  source: string | null;
  formatted_address: string | null;
  cached: boolean;
  cache_expires_at?: string;
  tried?: string[];
}

const SELANGOR_BOUNDS = {
  lng_min: 100.5, lng_max: 102.0,
  lat_min: 2.5,  lat_max: 4.0,
};

function hashQuery(query: string): string {
  const normalized = query.toLowerCase().replace(/\s+/g, ' ').replace(/,\s*/g, ', ').trim();
  return createHash('sha256').update(normalized).digest('hex');
}

function isValidCoords(lat: number, lng: number): boolean {
  return lat >= SELANGOR_BOUNDS.lat_min && lat <= SELANGOR_BOUNDS.lat_max &&
         lng >= SELANGOR_BOUNDS.lng_min && lng <= SELANGOR_BOUNDS.lng_max;
}

async function geocodeGoogle(query: string, apiKey: string): Promise<Partial<GeocodeResponse>> {
  const url = new URL('https://maps.googleapis.com/maps/api/geocode/json');
  url.searchParams.set('address', query);
  url.searchParams.set('components', 'country:MY');
  url.searchParams.set('key', apiKey);

  const res = await fetch(url.toString());
  const data = await res.json() as any;

  if (data.status === 'OK' && data.results?.length > 0) {
    const r = data.results[0];
    const lat = r.geometry.location.lat;
    const lng = r.geometry.location.lng;
    if (isValidCoords(lat, lng)) {
      return {
        latitude: lat,
        longitude: lng,
        accuracy: mapLocationType(r.geometry.location_type),
        source: 'google',
        formatted_address: r.formatted_address,
        place_id: r.place_id,
      };
    }
  }
  return {}; // empty = failed, caller should try fallback
}

async function geocodeNominatim(query: string): Promise<Partial<GeocodeResponse>> {
  const url = new URL('https://nominatim.openstreetmap.org/search');
  url.searchParams.set('q', query);
  url.searchParams.set('countrycodes', 'my');
  url.searchParams.set('format', 'jsonv2');
  url.searchParams.set('limit', '1');
  url.searchParams.set('addressdetails', '1');

  const res = await fetch(url.toString(), {
    headers: { 'User-Agent': 'SLGRVTRS-Dashboard/1.0 (research@ritz-analytics.workers.dev)' },
  });
  const data = await res.json() as any[];

  if (data.length > 0) {
    const r = data[0];
    const lat = parseFloat(r.lat);
    const lng = parseFloat(r.lon);
    if (isValidCoords(lat, lng)) {
      return {
        latitude: lat,
        longitude: lng,
        accuracy: mapNominatimType(r.type),
        source: 'nominatim',
        formatted_address: r.display_name,
        place_id: r.osm_type + '/' + r.osm_id,
      };
    }
  }
  return {};
}

function mapLocationType(type: string): string {
  const map: Record<string, string> = {
    'ROOFTOP': 'exact',
    'RANGE_INTERPOLATED': 'exact',
    'GEOMETRIC_CENTER': 'locality',
    'APPROXIMATE': 'locality',
  };
  return map[type] || 'locality';
}

function mapNominatimType(type: string): string {
  const exact = ['residential', 'suburb', 'neighbourhood', 'house', 'building'];
  const locality = ['village', 'town', 'hamlet', 'city_district', 'quarter'];
  const district = ['city', 'county', 'admin_level'];
  if (exact.includes(type)) return 'exact';
  if (locality.includes(type)) return 'locality';
  if (district.includes(type)) return 'district';
  return 'locality';
}

export async function POST(request: Request) {
  const { env } = await getCloudflareContext();
  const body = (await request.json()) as GeocodeRequest;
  const { query, dm_code, dun_code } = body;

  if (!query) {
    return NextResponse.json({ error: 'query is required' }, { status: 400 });
  }

  // 1. Check D1 cache
  const hash = hashQuery(query);
  const cached = await env.DB.prepare(
    `SELECT * FROM geocode_cache WHERE query_hash = ? AND expires_at > datetime('now')`
  ).bind(hash).first<any>();

  if (cached) {
    // Increment hit count
    await env.DB.prepare(
      `UPDATE geocode_cache SET hit_count = hit_count + 1 WHERE query_hash = ?`
    ).bind(hash).run();

    return NextResponse.json({
      dm_code: cached.dm_code || dm_code || null,
      query,
      latitude: cached.latitude,
      longitude: cached.longitude,
      accuracy: cached.accuracy_level,
      source: cached.source,
      formatted_address: cached.formatted_address,
      cached: true,
      cache_expires_at: cached.expires_at,
    } satisfies GeocodeResponse, {
      headers: { 'Cache-Control': 'public, s-maxage=3600, stale-while-revalidate=86400' },
    });
  }

  // 2. Google Maps (primary)
  const tried: string[] = [];
  let result: Partial<GeocodeResponse> = {};

  if (env.GOOGLE_GEOCODING_API_KEY) {
    tried.push('google');
    try {
      result = await geocodeGoogle(query, env.GOOGLE_GEOCODING_API_KEY);
    } catch (e) {
      console.error('Google geocoding error:', e);
    }
  }

  // 3. Nominatim (fallback)
  if (!result.latitude) {
    tried.push('nominatim');
    try {
      result = await geocodeNominatim(query);
    } catch (e) {
      console.error('Nominatim geocoding error:', e);
    }
  }

  // 4. Cache and return
  const isResolved = result.latitude != null;
  const ttl = isResolved
    ? (result.source === 'google' ? '+30 days' : '+90 days')
    : '+7 days';

  await env.DB.prepare(
    `INSERT OR REPLACE INTO geocode_cache
     (query_hash, raw_query, dm_code, latitude, longitude,
      accuracy_level, source, formatted_address, place_id,
      expires_at)
     VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, datetime('now', ?))`
  ).bind(
    hash, query, dm_code || null,
    result.latitude ?? null, result.longitude ?? null,
    result.accuracy || 'unresolved', result.source || null,
    result.formatted_address || null, result.place_id || null,
    ttl
  ).run();

  return NextResponse.json({
    dm_code: dm_code || null,
    query,
    latitude: result.latitude ?? null,
    longitude: result.longitude ?? null,
    accuracy: result.accuracy || 'unresolved',
    source: result.source || null,
    formatted_address: result.formatted_address ?? null,
    cached: false,
    tried,
  } satisfies GeocodeResponse, {
    headers: { 'Cache-Control': 'public, s-maxage=3600, stale-while-revalidate=86400' },
  });
}
```
